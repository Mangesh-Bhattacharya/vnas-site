Deployment, updates and building from source

1. Local development

Prerequisites: Go 1.26+, Node 22+. Optional: Rust (desktop), Android Studio / Xcode (mobile), Docker.

git clone <repo> vnas && cd vnas
npm ci && npm run build
cd server && go test ./... && go run ./cmd/vnasd serve      # API on 127.0.0.1:8080, data in ./data
npm run dev:web                                              # UI on http://localhost:5173 (proxies /api)

Tests:

cd server && go test -race ./...                             # server integration tests
VNAS_DATA_DIR=$(mktemp -d) VNAS_SIGNUP_MODE=open VNAS_AUTH_RATE_PER_MIN=1000 go run ./cmd/vnasd serve &
VNAS_E2E_URL=http://127.0.0.1:8080 npm test                  # client unit + end-to-end

2. Configuration (environment variables)

Variable Default Purpose
VNAS_ADDR 127.0.0.1:8080 Listen address
VNAS_PUBLIC_URL http://localhost:8080 External URL (origin checks, link URLs). Must be https in production
VNAS_DATA_DIR ./data Database, blobs, server-keys.json
VNAS_DB_PATH / VNAS_BLOB_DIR under the data dir Put blobs on a large disk / NFS / SMB mount
VNAS_TLS_CERT / VNAS_TLS_KEY – Native TLS (otherwise terminate at Caddy or nginx)
VNAS_TRUSTED_PROXIES – CIDRs whose X-Forwarded-For is honored
VNAS_SIGNUP_MODE invite closed / invite / open
VNAS_DEFAULT_QUOTA_BYTES 0 Per-user quota (0 = unlimited)
VNAS_AUTH_RATE_PER_MIN 10 Auth attempts per IP and per account
VNAS_SESSION_TTL / VNAS_SESSION_IDLE 720h / 336h Session lifetime
VNAS_TRASH_RETENTION 720h Auto-purge of trash
VNAS_VERSIONS_TO_KEEP 50 File versions kept
VNAS_WEB_DIR – Serve the built web client
VNAS_METRICS_ADDR – Separate listener for /metrics
VNAS_ALERT_WEBHOOK – JSON POST target for alerts

Secrets never go in config or code. The server generates server-keys.json (0600) on first
start. The agent reads passwords and API keys from *_FILE paths (Docker/K8s secrets, systemd
LoadCredential=, or a file readable only by its user).

3. Production on a home server or VPS (Docker, recommended)

  1. Point a DNS name at the machine. Open ports 80 and 443 (on a home network, forward them on the
    router, or use a free Cloudflare Tunnel or Tailscale Funnel to avoid opening ports).
  2. Then: 
    cd deploy && cp .env.example .env && nano .env          # set VNAS_DOMAIN, ACME_EMAIL
docker compose up -d
docker compose logs -f vnasd
  3. Open https://your-domain, create the first account (it becomes admin), and save the recovery key.
  4. Turn on two-factor authentication: Settings → Two-factor authentication.
  5. Invite others: Admin → Create invite (or docker compose exec vnasd vnasd invite user).
  6. Set up backups (§5).

LAN-only / no domain: run vnasd with VNAS_TLS_CERT/KEY from mkcert, or put it behind Tailscale
(which provides the TLS).

Without Docker

  • Linux: use deploy/systemd/vnasd.service (sandboxed) plus Caddy from your distro.
  • Windows: download vnasd-windows-amd64.exe, then
    setx VNAS_DATA_DIR D:\vnas and register it as a service with NSSM or sc.exe create vnasd binPath= "C:\vnas\vnasd.exe serve".
    Put Caddy for Windows in front.
  • macOS: vnasd-darwin-arm64 + a launchd plist, with Caddy via Homebrew.

Kubernetes

deploy/k8s/vnas.yaml: restricted Pod Security, read-only root filesystem, NetworkPolicy, probes,
single replica with Recreate (SQLite).

4. Monitoring and alerts

  • /healthz, /readyz for orchestrators; the container HEALTHCHECK uses vnasd healthcheck.
  • /metrics (Prometheus): vnas_http_responses_total{class}, vnas_audit_events_total{action}
    (for example auth.login.fail), vnas_disk_free_bytes, vnas_stored_bytes, vnas_users.
  • Built-in alerts to VNAS_ALERT_WEBHOOK (deduplicated, at most once per hour per key):
    ≥25 failed sign-ins in 10 min (spraying), ≥5 failures on one account, disk <10% / <5% free,
    audit write failure. Free targets: self-hosted ntfy (phone push), Gotify, Alertmanager.
  • Weekly: docker compose exec vnasd vnasd audit-verify.

5. Backup, restore, disaster recovery

What to protect:

Item Why How
vnas.db Accounts, structure, wrapped keys, audit vnasd backup-db (consistent online snapshot)
blobs/ Encrypted file contents File copy (immutable, content-addressed)
server-keys.json TOTP seeds, audit signing Copy; if lost, users re-enrol TOTP. Data is unaffected
Users' recovery keys The only way back in if a password is forgotten Each user prints theirs. Admins cannot help
restic password Decrypts the backups Store off-site (password manager plus a paper copy) 
export RESTIC_REPOSITORY=/mnt/usb/vnas-backup  RESTIC_PASSWORD_FILE=/root/.restic-pass
restic init                       # once
deploy/backup/backup.sh           # daily: cron "15 3 * * *"

Follow the 3-2-1 rule: one local USB copy plus one off-site repository (a second NAS at a friend's house
over SFTP, or B2/S3 storage). The data is encrypted twice, so any storage provider can be used.

Restore / DR on a new machine: install vnasd, run deploy/backup/restore.sh latest /var/lib/vnas,
start, run vnasd audit-verify, then sign in. Clients rebuild their caches automatically. Test a
restore every quarter. RPO = backup interval (≤ 24 h); RTO ≈ restore time (minutes for metadata,
plus blob download time).

Upgrade rollback: take vnasd backup-db pre-upgrade.db, upgrade, and if needed stop, put the
snapshot back as vnas.db, and run the previous image tag. Migrations are forward-only.

6. Updates and security patches

Component How users get updates Integrity
Server image docker compose pull && docker compose up -d (pin VNAS_VERSION). Watchtower can automate this cosign signature: cosign verify ghcr.io/<org>/vnas:<tag> --certificate-identity-regexp '.*' --certificate-oidc-issuer https://token.actions.githubusercontent.com
Server binary Replace the file, restart cosign verify-blob --bundle SHA256SUMS.sigstore.json SHA256SUMS, then sha256sum -c
Desktop Built-in updater prompts and installs minisign signature checked against the key compiled into the app
Mobile App stores; signed OTA for JS fixes Store signing + Expo code signing
Web Automatic on next page load Served by your server

Release process: semver tags vX.Y.Z trigger .github/workflows/release.yml. Security fixes are
PATCH releases with a changelog ### Security section and a GitHub Security Advisory.

7. Building installers and apps from source

Server binaries

cd server
GOOS=linux  GOARCH=arm64 CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o vnasd-linux-arm64 ./cmd/vnasd
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o vnasd.exe ./cmd/vnasd
docker build -t vnas:local ..

Desktop (Windows .exe/.msi, macOS .dmg/.app, Linux .AppImage/.deb/.rpm)

Prerequisites: Rust stable; Linux needs libwebkit2gtk-4.1-dev libsecret-1-dev librsvg2-dev;
Windows needs WebView2 (preinstalled on 10/11); macOS needs the Xcode command line tools.

npm ci && npm run build -w packages/core
cd apps/desktop && npm install
npx tauri icon ../web/public/icon.svg               # generate icons once
npx tauri signer generate -w ~/.tauri/vnas.key      # once: updater keypair → put pubkey in tauri.conf.json
TAURI_SIGNING_PRIVATE_KEY=$(cat ~/.tauri/vnas.key) npx tauri build
# output: src-tauri/target/release/bundle/{nsis,msi,dmg,macos,appimage,deb,rpm}

Code signing (optional but recommended): Windows via Authenticode certificate, Azure Trusted Signing,
or SignPath (free for OSS); macOS via Developer ID plus notarization (requires an Apple Developer account).
Unsigned builds work but show SmartScreen / Gatekeeper warnings.

Mobile (Android APK/AAB, iOS IPA)

npm ci && npm run build -w packages/core
cd apps/mobile && npm install
npx expo prebuild                                # generates native projects
npx expo run:android --variant release           # local APK (needs Android SDK)
# or cloud builds (EAS free tier):
npx eas build -p android --profile preview       # installable APK for sideloading
npx eas build -p android --profile production    # AAB for Google Play
npx eas build -p ios --profile production        # IPA (needs an Apple Developer account)

Free distribution options for Android: direct APK, F-Droid (reproducible builds), Obtainium.
iOS requires the App Store or TestFlight; the PWA (Add to Home Screen in Safari) is the free
alternative and supports offline use.

Before the first mobile release: confirm that react-native-libsodium exposes every libsodium
function @vnas/core uses (crypto_pwhash, crypto_kdf_derive_from_key, crypto_aead_xchacha20poly1305_ietf_*,
crypto_box_seal(_open), crypto_sign_*, crypto_generichash, crypto_hash_sha256, memzero).
Run the core test suite on a device. Any gap can be filled with a small native module or a JS fallback for that one function.
