vNAS operator manual (plain language)

This guide is for whoever sets up vNAS for a household or small team. No programming needed.

The three things that matter most

  1. Your password unlocks your data, and nobody can reset it. Not the admin, not the developers.
    This is what makes vNAS private.
  2. When you create an account you get a recovery key. Print it and keep it somewhere safe.
    It is the only way back in if you forget your password.
  3. Back up the server (section 6). Encryption protects privacy, but only backups protect against a dead disk.

1. Install the server

Pick one computer that stays on: a mini PC, an old laptop, a NAS with Docker, a Raspberry Pi 5, or a
small cloud server.

Easiest: Docker (Linux, Windows, macOS)

  1. Install Docker Desktop (Windows/macOS) or Docker Engine (Linux).
  2. Download vNAS and open the deploy folder in a terminal.
  3. Copy .env.example to .env and fill in:
    • VNAS_DOMAIN: the web address you will use (for example nas.smith-family.org). It must point to this computer.
    • ACME_EMAIL: your email, used for the free HTTPS certificate.
  4. Run docker compose up -d. After a minute, open https://<your domain>.

No domain, or don't want to open your router? Install Tailscale (free for personal use) on the
server and your devices, then use the Tailscale name as the address.

Without Docker

  • Windows: put vnasd.exe in C:\vnas, run vnasd.exe serve (or install it as a service, see DEPLOYMENT.md §3).
  • macOS / Linux: run ./vnasd serve. On Linux, the included systemd service starts it automatically.

2. Install the apps

Device How
Windows Run the vNAS_x.y.z_x64-setup.exe installer
macOS Open the .dmg, drag vNAS to Applications
Linux .AppImage (any distro), .deb (Ubuntu/Debian) or .rpm (Fedora)
Android Install the APK (allow "install unknown apps" once), or use F-Droid / Play Store if published
iPhone / iPad App Store / TestFlight build, or open your vNAS address in Safari → Share → Add to Home Screen
Any browser Just visit your vNAS address

On first launch, enter your server address, email and password. On phones you can turn on Face ID or
fingerprint unlock; on desktop, tick Remember on this device to use the system keychain.

3. First account, users, roles and permissions

  1. The first account created becomes the administrator. Do this right after installing.
  2. Turn on two-factor authentication: Settings → Set up authenticator app (use Aegis, 2FAS, or any
    authenticator), then store the 10 backup codes with your recovery key.
  3. Add people: Admin → Create invite, choose a role, and send them the code. They enter it on the sign-up screen.
Role Good for
admin You, plus a trusted backup admin. Manages accounts but cannot see anyone's files
user Family members and colleagues
readonly Someone who should only look (e.g. an accountant viewing shared receipts)
guest Temporary access to just what you share with them

Sharing: in Drive, Share gives a person access to the whole drive (as editor or viewer).
For one file, Link creates a private link that expires (you choose how many hours). The link
itself contains the key, so send it over a channel you trust.

Quotas: Admin → click the quota cell for a user.
Disable an account: Admin → click active to switch it to disabled (signs them out everywhere).

4. Everyday use

  • Drive: drag files in. They are encrypted on your device before they leave it. Old versions are kept automatically.
  • Notes: Markdown notes with tags; they save automatically.
  • Passwords: add entries, use Generate for strong passwords, and Security check to find weak or reused ones.
    Copied passwords clear from the clipboard after 30 seconds.
  • Offline: everything you have opened on a device is available offline. Changes made offline
    sync when you reconnect. If two devices changed the same note, you get both versions (one marked conflict).
  • Trash: deleted items stay in Trash for 30 days.
  • Lost phone or laptop: from any other device, Settings → Devices → Revoke. Then change your password.

5. Using the AI assistant safely

  • The assistant is a separate account that only sees what you share with it. Start small: share
    your Notes, not your Passwords. vNAS will never let the assistant read password entries anyway.
  • By default it runs entirely on your server with a free local model (Ollama), so nothing leaves your network.
  • Setup: create an account for it (Admin → invite), share spaces with it as viewer, start it with
    docker compose --profile ai up -d, then paste its token in Assistant → Connection.
  • Cloud AI (OpenAI and others) is off unless the admin enables it for specific spaces. Even then,
    emails, card numbers, keys and passwords are masked before sending.
  • The assistant cannot change, move, share or delete anything. It only reads and suggests.
  • Treat its answers as suggestions and check the cited sources.

6. Backups and restore

Set this up on day one (details in DEPLOYMENT.md §5):

  1. Plug in a USB disk, or get a cheap off-site storage account (Backblaze B2, or a friend's NAS over SFTP).
  2. Install restic (free). Create a backup password and store it in your password manager and on paper.
  3. Run deploy/backup/backup.sh every night (your admin or a cron job does this).
  4. Every few months, practice a restore onto a spare computer with restore.sh.

Backups are encrypted, and the files inside were already encrypted, so it is safe to keep them in the cloud.

What if…

Problem Fix
Forgot password Sign-in screen → recovery with your recovery key
Lost recovery key and forgot password The data is unrecoverable. This is the cost of real privacy. Make sure everyone stores their key
Lost authenticator app Use one of the 10 backup codes
Server died Restore from backup onto any computer; apps reconnect
Disk almost full You'll get an alert if a webhook is configured; add storage or set quotas

7. Keeping it secure and up to date

  • Update monthly, or immediately when a security release is announced:
    docker compose pull && docker compose up -d. Back up first.
  • Desktop apps update themselves (you will be asked). Phone apps update through the store.
  • Check Admin → Audit log occasionally for unfamiliar sign-ins or failed attempts.
  • Keep the server OS updated, and use full-disk encryption on the server and laptops.
  • Keep sign-up on invite mode if the server is reachable from the internet.
